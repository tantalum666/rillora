# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Durable public-entry rule: signed-out Home, Account and any mobile-equivalent top-level surface use product, task and account language. Do not promote `Free`, `no card`, plan names or pricing in those entry controls; commercial explanation belongs only after explicit plan-review or named paid-capability intent.

Durable consent rule, updated by the Owner's 2026-09-06 direct-hosted decision: iOS private intents start hosted authentication directly. Do not restore the native email/method intermediary. The deployed hosted consent form and receipt are authoritative; never manipulate private widget DOM. Web retains its compact pre-auth checkbox until a separately tested Web migration.

Durable interaction rule, 2026-09-09: every child and multi-level page should lead with controls, imagery and actual state feedback. Avoid title/subtitle/intro/footnote stacks. Place long detail behind explicit disclosure and consequential acknowledgements at the relevant action. Public exploration stays useful after session expiry; browsing never requires authentication. Keep local selections and the pending category when returning from Account. Use the working references and route coverage in `../../docs/interaction-experience.md`.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

Zero-revenue legal publication uses the separate `build:legal` contract. Run the repository wrapper `tools/legal/run-legal-sites-build.sh`, the complete Web tests and `test:legal-sites`, then package only validated `dist/` with `tools/legal/package-legal-sites.sh`. The final artifact must use `worker/legal-index.js`, embed the HTML shell in the Worker, leave no client HTML object for Sites clean-URL handling, contain only the seven legal routes, make no app-authored API／auth／analytics／optional-storage request, and reject Account／API／unknown／write routes. Sites／Cloudflare may still supply aggregate hosting analytics and the host-only necessary `__cf_bm` bot-protection cookie; do not claim zero provider telemetry or zero response cookies. The 2026-09-03 accessible project version 3 and `legal.rillora.xyz` are the public baseline. Any future change must save and deploy a newer version, then repeat anonymous route／header／rendered-page verification before it replaces that baseline.

Durable account/editor rule, 2026-09-11: use Sign in / Sign up even after expiry. Guests may open received invitations; outgoing sharing requires login. Keep invitation return through signup and require explicit acceptance. Matter entry is one continuous category-specific form with required locators and Notes last; no Details / Directions / People tabs or consumer simulation/motivation clutter. Follow `../../docs/account-matter-ux.md`.

Durable invitation/motion rule, 2026-09-11: use Invite someone for outgoing Person/Access/Link creation and Accept a received invitation for incoming links under Shared with me. Keep real generated folio imagery and state-driven motion, with reduced-motion alternatives. Refresh clean sharing state on return; clear obsolete QR after acceptance/revocation/version change and preserve dirty drafts. Follow `../../docs/invitation-motion-ux.md`; do not introduce an incomplete commercial paywall.
