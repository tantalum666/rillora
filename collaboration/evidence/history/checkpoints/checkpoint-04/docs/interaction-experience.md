## Interaction rules

1. One current task per surface. Avoid title + subtitle + intro + footnote repeating the same point.
2. Use selection controls, category symbols, live relationships, native focus and brief state transitions. Do not animate prose just to make it move.
3. Browsing a category, exploring the diagram or reading a guide does not authenticate, create data or collect agreement.
4. Preserve the original intent through authentication. An Add action resumes its editor and selected category; cancel returns to the same public context.
5. Editing has visible fields, preserved local state and guarded exit when dirty. Optional detail is collapsed; necessary fields and errors remain findable.
6. Rehearsal progress comes only from the current server response and is always identified as simulated. Changing a scenario invalidates the previous scenario's displayed result.
7. Export is Review -> Format -> Save. Exact consequential acknowledgements remain at the save action; no file or key is created by merely selecting a format.
8. Reduce Motion removes nonessential transforms and movement. Text size is not capped to preserve a composition. All app-owned targets remain at least 44pt.
9. Keep provider/system credential pages recognisable and preserve their security semantics. A visual change does not prove identity, legal acceptance, external delivery or release.

## Detail and exit behavior

- Field labels and errors stay visible; optional material uses deliberate disclosure. Current provider instructions show one step, with the original URLs and fuller details reachable.
- Web dialogs use native HTML modal focus and explicit Keep editing / Discard actions. iOS whole-field focus targets and whole-row acknowledgement checkboxes are interactive throughout their visible bounds.
- Unkept recovery keys survive a cancelled exit or refresh. A visible return-to-key action precedes an explicit abandon choice. Opening a share sheet or downloading does not automatically assert the key was kept.
- Private role/rehearsal state is never inferred from animation, category selection or a public demonstration. All mutation result labels come from the current service response.

Motion follows Apple's [purposeful, optional feedback guidance](https://developer.apple.com/design/human-interface-guidelines/motion); the UI must still communicate state when movement is reduced.
