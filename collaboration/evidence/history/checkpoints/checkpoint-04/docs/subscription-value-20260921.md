## 当前事实与问题

- 现有Family并非只有更多联系人。另有一位受限建议贡献者、共同检查、应用内复核日期，以及获批准更正的前后记录。完整共同编辑、全计划历史、自动外部通知和平台政策监测尚不是已交付能力。参见[共同维护](family-maintenance.md)。
- Free1／Family5和到期旧版本已在先前测试环境验收。本轮读了目录、商业合同及共享／维护SQL，没有重复云端测试或实际收费验收。
- 到期后，主人保留基础资料编辑／导出／删除；本人选定的一位Free联系人继续获准更新，其余已接受的联系人只读取有日期的付费期授权副本。新事项、新值和扩大授权不能进入旧副本。撤销、缩小范围和源资料删除继续生效。
- 这阻止“买一个月永久保留多人实时服务”，却无法让一份很少变化的旧资料失去实用价值。用户下载的合法副本、截图、手动转发也不能由服务器召回。只买一个月并取消，是月付合同允许的正常使用。

## 金额情景

按当前[目录](../config/product-catalog.json)，观察窗口为12个月，单位为一户。以下是不同支付模式的算术，不是实际用户行为；未扣手续费、税、退款或成本。

| 假设支付模式 | 12个月累计支付 |
| --- | ---: |
| 只订1个月 | US$9.99 |
| 每季度订1个月，共4个月 | US$39.96 |
| 买一个年付周期 | US$88.80 |

年付便宜25.9%只适用于与连续12次月付比较。它不会吸引只需要1–4个月服务的人。一年只付一个月的收款是年付金额的11.25%；不能仍按88.80计算这类客户收入。切为年付也可能降低转化，不能假设客户数量不变后直接计算利润提升。[复算结果](../output/qa/rillora-subscription-value-20260921/scenarios.json)，[执行Notebook](../output/qa/rillora-subscription-value-20260921/billing-frequency.ipynb)。

## 适合保留的限制

| 时点／能力 | 规则 |
| --- | --- |
| 取消自动续费 | 当前已付周期继续有效，到期才降级 |
| 付费期有效 | 最多5位获准的实时接收人，待接受邀请也占名额 |
| 到期后 | 只保留本人指定的1位实时接收人；其他已接受者停在各自有证据的授权副本 |
| 共同维护和新增付费处理 | 没有当前权益就停止新增任务／更正／付费历史生成；原有基础资料及退出权利保留 |
| 切换免费联系人 | 原实时关系先停止，再启用新关系；不由切换操作刷新已停更的付费副本 |
| 重新订阅 | 只在新的有效付费期恢复选定服务，不自动复活已撤销联系人或扩大权限 |

这些关键边界已有实现基础，不能作为本轮新加的功能宣传。服务端时钟、事务名额、回调幂等和每次读取／写入的权益校验防止绕过；它们不能防止所有人工抄录和多次正当短期购买。无需为了防多账号而新增侵入性设备追踪或家庭IP封禁。

不建议增加隐藏最低订阅期、按月收费却强绑一年、先扣钱再等几个月才解锁、数据导出收费、取消立即清空或让已经获准的家人突然失去全部资料。云端副本也不承诺永久托管，仍受明确的保留和撤销合同约束。

## 年费需要交付什么

“多四个人”和季度提醒本身不足以证明88.80美元价值。优先验证用户是否愿意为以下持续工作付费；不为增加功能表长度扩充首发。

| 持续服务候选 | 已有基础 | 真正需要补齐的交付 |
| --- | --- | --- |
| 多位家人的资料持续同步 | 逐人授权、实时／旧副本及撤销已实现 | 清楚展示哪些人拿到哪一版，不能把已发送等同于已看懂 |
| 关键变化通知与确认 | 共同检查和应用内任务已实现 | 可靠的外部通知、送达失败／重试、偏好与频率限制；仅向获准者发送无敏感正文的通知 |
| 与具体账号有关的官方流程变化 | 18份指南与事项本地匹配已有 | 按官方原文检查重要变化，经内容核验后给受影响用户新的原链接和具体待办；不能收费出售仍应公开的原始指南 |
| 资料变动的可追溯记录 | 仅获批准的provider/location更正历史 | 若验证为真实需要，再扩充有范围和保留上限的版本／比较；不得宣称已有全计划历史 |

首发最值得补齐的是“资料改变→获准家人收到通知→确认／报问题→主人知道结果”的完整服务链。平台变化提醒是下一项差异化实验，不应在未具备来源核验、误报控制与通知交付前写进可购买承诺。不能把正常运维、安全修补或花哨年度报告单独包装成不可替代的付费利益。

如果用户完成一次整理后明确不再需要持续服务，应承认这类需求不适合订阅。未来可以验证独立的一次性整理／高级交付产品，但不能把当前免费的基本导出拿走，也不承诺一次付款终身云托管。本轮不新增此商品、不另定价格。

## 如何验证，避免仅让财务表好看

保留现有首批30–50名测试者及至少3笔真实支付的运营检查约定；它不足以验证年续费。先按预先固定的报价和已交付服务观察付费转化、首个付费任务完成、取消原因及支持成本，再观察30／90天真实家庭协作或资料变化。主要指标不采用日活、打开次数或提醒点击率。

“我只想整理一次”和“我需要持续服务但不信任先付一年”应分开记录；二者对应不同产品／价格问题。实际年续费要等完整续费资格窗口，不能拿90天留存推算成已经验证。
