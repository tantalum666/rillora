# Digital Legacy Project Agent Entry Point

本文件适用于整个仓库。它是上下文与执行路由，不是产品规范、法律意见或发布证明。

## 开工协议

在一个全新的工作流开始时：

1. 盘点并完整阅读所有项目自有的 `.md` 文件；排除依赖、缓存、构建产物和第三方包。
2. 先读 `docs/product.md`，再按其中的 Authority Map 路由到本次任务所需文件。
3. 检查上一工作流是否更新了 `docs/handoff.md`、相关规范、`docs/decision-log.md` 和
   `docs/journey/PROJECT_JOURNEY.md`。
4. 不把聊天摘要、研究报告、概念图、代码、模拟器截图和真实市场结果混成同一种证据。

上下文压缩后的快速恢复路径：

1. 本文件；
2. `docs/product.md`；
3. `docs/handoff.md`；
4. `docs/decision-log.md`；
5. 本次任务路由文件和所有将被修改的文件。

## 权威顺序

发生冲突时按以下顺序处理，禁止把相互冲突的历史方向折中拼接：

1. Owner 最新且明确的指令；
2. 适用法律、平台官方规则和可验证的安全事实；
3. `docs/product.md` 中标记为 `LOCKED` 的决定；
4. `docs/decision-log.md` 中较新的明确决定；
5. 当前任务的聚焦规范；
6. 已选定的视觉目标；
7. 当前代码和运行结果；
8. 研究证据、竞品、概念和历史记录。

当前代码只能证明“已经实现了什么”，不能自动推翻已锁定的产品意图。研究只能提供证据，不能自动成为产品决定。

## 自主推进协议

- 默认连续推进到下一个真正需要Owner判断的关键门，不因阶段完成而等待Owner重复发送“继续”。
- Owner于2026-09-09最新明确：“本项目全部默认授权与确认”。本项目已有目标范围内的必要操作按此默认授权连续推进，不再沿用2026-08-18的旧逐项确认门。这包括当前已具体说明的Apple登录替换密钥创建、受保护保存、传入既有Auth0 Apple连接、旧密钥撤销和入口恢复。授权不是完成证明，也不意味着任意扩大任务目标。
- 可逆的产品、设计、工程、文档和验证决定由Agent基于权威文件、证据和当前结果自行作出，并在收尾记录取舍与证据边界。
- 已有明确目标、必要信息和可用能力时直接执行。只有缺少无法自行取得的必要信息、平台要求本人完成的登录／验证码／交互，或更高优先级工具规则要求时，才交回对应步骤；必须说明具体阻塞及来源，不把历史授权门重新当作待确认项。
- 工具或环境受限时，优先采用不降低既有安全与证据标准的可逆替代路径；替代路径、未完成项和不能证明的内容必须明确记录。

## 项目硬约束

- 全球愿景不等于宣称一套流程在所有国家都具有遗嘱法律效力。
- 首轮MVP必须同时提供Web与iOS核心路径；共享领域模型和API，但使用各平台原生交互。
- MVP遵循“地图而不是密码”：不得保存银行卡密码、完整助记词或可直接转账的单点秘密。
- 不得仅凭用户未登录或未签到自动判定死亡并释放敏感资料。
- 死亡、失能和失联是三个不同流程，不能共用一个含糊触发器。
- 资产存在、合法授权、账号访问、信息披露和所有权转移是不同概念，界面和文案必须区分。
- 未选定视觉目标前，不创建正式 `DESIGN.md`，不把临时样式写成权威设计系统。
- 任何“可用、已验证、全球合法、端到端加密、已删除、已转移”声明都必须有与该声明同级的证据。

## Web与iOS纪律

- 两端共享术语、状态、权限、核心数据结构、实验事件和安全边界。
- 不要求页面像素相同；Web应发挥大屏编辑与执行人门户优势，iOS应发挥快速录入、设备认证和通知优势。
- 首轮市场验证开始前，两端都必须完成 `docs/platform-contract.md` 定义的核心闭环。
- 邀请接收人不得被强迫安装iOS App；安全的Web入口必须存在。

## 收尾协议

每次有意义的产品、设计、工程、研究或验证工作完成后：

1. 更新实际改变的聚焦规范；
2. 如有新批准、否决或取代关系，追加 `docs/decision-log.md`；
3. 更新 `docs/handoff.md` 的当前状态、证据边界和唯一下一步；
4. 向 `docs/journey/PROJECT_JOURNEY.md` 追加“目标 -> 尝试 -> 判断变化 -> 结果 -> 未完成项”；
5. 检查所有Markdown链接、日期、状态和术语是否一致。
