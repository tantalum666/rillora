# Rillora：低成本获客执行计划

Status: READY TO EXECUTE / NO OUTREACH OR AD SPEND STARTED
Last updated: 2026-10-18 (Asia/Hong_Kong)

这是Owner要求的营销阶段工作计划。事实来自[部署前复核](readiness-audit-20261018.md)、[后续正式MCP／Registry交付](../architecture/customer-mcp-20261018.md)、[Google地图结果](../architecture/google-sitemap-20261018.md)及产品合同；客群、渠道效果和时间分配是待验证假设。当前没有CRM机会、真实客户承诺、可计算CAC或完整营销归因基线，不为制定计划强行购买CRM或数据服务。

## 目标与定位

先证明一小批家庭真的用得上，再追求曝光。沿用[MVP](../mvp.md)的30—50名首轮受邀测试者目标，不把关注、注册或生成AI答案当激活。第一批从其中10位愿意实际尝试的人开始，观察至少5组规划者／接收人是否真的找到获准查看的下一步，再扩大。

主张：**让关心你的人知道重要资料在哪里，以及下一步该找谁。** 英文：**Give someone you trust a clear place to start.** 演示只用合成事项。不宣传“合法电子遗嘱”“自动继承”“永久绝对安全”“全部AI已支持”或“失联即释放”。

首批两个假设客群：

1. 在已开放服务市场生活、有伴侣或家属、账号与文件分散的人；触发情境是搬家、跨国生活、家庭分工变化。需要的是“家人能找到”，而不是研究一套新软件。
2. 独立开发者／创作者／小生意负责人，需要可信的人知道域名、订阅、工作文件和服务联系入口。先试个人事务整理，不承诺团队灾备、企业SLA或客户数据托管。

不按年龄泛投，不利用刚丧亲的人或制造死亡恐惧。中文内容服务实际开放市场的中文用户，不代表中国大陆版已开放。Web已开放可用；iOS下载／订阅宣传需以真正商店发布和Apple新购就绪为准。

## 四周怎么做

时间从首个渠道正式发布开始计算，不假装现在已有获客结果。每周总投入建议6—8小时，其中公开内容约3小时、体验反馈2小时、数据复盘1小时、针对阻塞的修正1—2小时。每周最多2条公开帖子，沿用[已有内容计划](../../config/content-program.json)。

| 阶段 | 具体动作 | 交付与判断 |
| --- | --- | --- |
| 准备期／本轮 | 全量盘点、修包规则、6篇文章意图映射；准备双语文案、商店草稿和记录表 | 本轮已完成文件；不把草稿记为已投放 |
| 第1周 | 选一个英文渠道和一个中文渠道；优先Owner已有账号／熟悉社群。各发布1条“第一项资料怎么整理”，链接对应语言清单。仅向已表示愿意的人演示 | 目标取得10位明确愿意尝试者，不是购买名单。记录来源、投入时长和参与同意；不索要真实资料正文 |
| 第2周 | 保持相同渠道，各1条“家人能看到什么”；用合成事项录制20—30秒演示；邀请愿意的人完成5项＋1位接收人任务 | 按实际行为找阻塞：不创建／不分享／对方找不到；先修理解或流程，暂不加功能 |
| 第3周 | 继续有效渠道；把最常见问题补到已有文章，保留真实更新日期。发1条密码工具区别、1条撤销边界 | 有明确获准用途时，请已完成任务的人自愿分享公开清单；不用解锁功能、红包或好评交换推荐 |
| 第4周 | 对比两渠道的有效任务与时间成本；停止没有有效尝试的渠道。完成首轮30—50人招募是否可行的判断 | 达到原MVP方向门槛才扩张。低样本不做“显著提升”或LTV推算；广告预算仍为0 |

发布前先核对该账号和社区规则，文案明确开发者身份。英文可优先选允许相关讨论的家庭／跨国生活社区或Owner已有X／LinkedIn；中文优先Owner已有小红书／中文社群。只选两处执行，不同时铺十个平台。具体社区和接收人尚未指定，当前没有发送授权或已连接发布账号，故只准备成稿。

[Reddit官方](https://support.reddithelp.com/hc/en-us/articles/28012014962580-How-do-I-keep-spam-out-of-my-community)要求遵守各社区的自我推广规则，不存在适用于所有社区的统一发广告配额。不要批量私信、复制评论或伪装普通用户推荐自己的产品。

## 渠道优先级与最低成本打法

| 渠道 | 做法 | 衡量与停止条件 |
| --- | --- | --- |
| 现有官网搜索 | 保留6篇核心文章；Google地图已解析两语言共28URL，接着看已索引URL与真实查询，再补对应内容 | 页面曝光→有效点击；连续4周无数据先查索引，不判需求失败，不购买外链 |
| 场景内容与演示 | 同一合成场景改成中英文各一条，语气自然，不逐字机器翻译；一个问题＋一个行动入口 | 2次合规发布后如无人愿意尝试，先改受众／开头，不扩发10条相同内容 |
| 用户自愿带来的家庭扩散 | 用现有接收人Web入口；在用户成功后允许其自愿分享公开教程 | 联系人接受是产品使用，不自动算新获客；只有独立建立自己地图才计新规划者 |
| 专业转介 | 后续向明确愿意交流的独立整理顾问／家庭财务教育者展示公开教程 | 先3次需求交流，确认其用户确有定位资料的困难；不承诺法律合作、不付介绍费、不群发 |
| AI公开推荐 | 每周固定问题抽样，核对品牌事实／引用URL；把错误修在公开事实页 | 引用不是注册；保留实际回答日期／平台／联网状态，不拿自己这次带项目上下文的回答做评测 |
| MCP与插件 | 正式服务、Codex实际任务与官方Registry已就绪；先用已验证的Codex路径获得真实反馈，OpenAI消费端目录在Owner暂后的身份验证后续办 | 连接后能解释选定事项／指出缺项且拒绝越权；无实际客户使用前不继续铺长尾CLI；不把登记或7份配置宣传为全部消费端通过 |
| App Store | 下一版名称／副标题／关键词与前3张截图讲清用途；当前审核不改 | 展示→产品页→首次下载→有用地图；Apple官方统计不足门槛时记不可用 |
| Product Hunt／付费广告 | 留待Web核心价值、支持准备和小批用户结果稳定 | 不把首发榜单当留存。未形成真实付费队列前不买榜、买评、投泛流量 |

## 指标与归因：先把分母记录对

| 指标 | 定义与数据来源 | 当前限制 |
| --- | --- | --- |
| 搜索可见度 | Search Console的具体页面／查询曝光、点击；Bing索引及AI报告 | 站点地图解析不是曝光；后台延迟／小样本不填0 |
| 首项与五项完成 | API已有first_item_added／five_items_completed事件，限合规聚合 | 没有当前真实客户队列读回，不声称已完成营销报表 |
| 有用共享地图 | 5项＋关键意愿＋1位联系人接受＋接收人找到获准方向 | 接受／理解不是现成营销事件；首轮可用自愿任务反馈，不能虚构自动埋点 |
| 真实付费／退款／取消 | 实际支付账本的净结果，区分测试、退款及同一家庭 | 不用Checkout创建数、Sandbox或自己付款当市场需求 |
| 获客成本 | 现金CAC＝可归因获客支出／新增真实付费家庭；完整CAC另加内容与沟通时间 | 无新增付费家庭或归因不足时为N/A，不是0；不拿年费直接当毛利 |
| 30／90天维护 | 同一实际队列是否复核有变化的事项与共享 | 新队列尚未到期时标未成熟，不预测已留存 |

沿用[第一方事件合同](../product-events.md)，不开广告像素、跨站追踪Cookie或指纹。草稿里的UTM只为渠道命名；现有官网不把这些参数持久归因到账号，跨域／登录链可能丢失，所以不能据此计算精确渠道收入。首轮用平台聚合、无个人标识的渠道台账、用户自愿说明来源；需要新增埋点时先做明确隐私设计。

App Store已有数据后再生成真实campaign link，记录Apple返回的provider token，不能自行编造pt。Apple当前对小样本指标有阈值，缺值不代表零下载；[官方活动链接说明](https://developer.apple.com/help/app-store-connect-analytics/acquisition/campaign-links)。

## 预算与扩张门

本轮新增工具、广告、模型调用预算均为0；使用既有网站、免费站长平台、可用账号和合成素材。既有基础设施、平台分成、本人时间并不免费。延续[单位经济](../unit-economics.md)的现金／劳动分开口径；不改Web USD88.99／年、Apple美国USD119.99／年及当地商店价，不加折扣、免费试用或返利。

原MVP在30—50位测试者中的方向信号保持：至少半数完成五项、至少三分之一发真实邀请、多数受邀联系人接受、至少5组完成找方向任务、至少3位真实付款或原合同允许的强承诺。以上是探索门槛，不是保证达到或统计显著结论。达到后才研究更大的真实付费队列和小额广告实验，另定预算，不先开广告账户或扣款。

## App Store：ASO 和 AEO 分工

商店内部搜索与下载转化通常叫ASO；AEO／GEO主要处理AI答案中的发现与引用。不是改几个关键词就能让系统自动推荐，也没有可靠依据承诺某个词的搜索量或排名。

下一版草稿在[aso-vnext.json](../../config/marketing/aso-vnext.json)，与当前在审listing分开。建议英文名称Rillora: Digital Legacy；中文Rillora：数字遗产整理。副标题讲具体用途；关键词补充名称／副标题没覆盖的意图，不放竞品商标、无关“AI”或误导的遗嘱生成词。

Apple名称／副标题各不超过30字符；关键词文档一处写100字符、平台参考写100字节，所以本稿同时检查Unicode字符及UTF-8字节上限，中文也控制在100字节内。推广文本170字符且不承担关键词排名作用。说明要真实，保留现有信息整理／共享／官方指引／退出边界。[产品页规则](https://developer.apple.com/app-store/product-page/)、[平台字段](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information/)。

前3张截图的故事顺序：①重要资料有位置；②每个人只看你选的内容；③留一份能找到起点的副本。英文已有4张iPhone、中文已有2张，下一版补齐中文共享／副本故事才有同等转化表达；使用当前合成实机画面，不生成假UI。第四张“从一项开始”。当前在审10张图不替换。

主语言英文保留；简体中文完整单列，商店按支持语言及用户／商店规则选择显示，不能只按地区一对一推断，也不自动翻译全部素材。[本地化规则](https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information)。香港繁体素材先列需求观察，不能把简体UI说成已经支持繁体。

上线后核对Apple实际分配的App Tags是否相关；官方当前只在美国显示且基于en_US元数据等生成，不能自己任意填词或承诺覆盖香港。[App Tags](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-tags)。

PPO要到Ready for Distribution且有足够流量后，先比较1个截图顺序变量，不同时改名字、词和图；以Apple实际置信结果判断，小样本结论可能不成立。[PPO资格](https://developer.apple.com/help/app-store-connect/create-product-page-optimization-tests/overview-of-product-page-optimization)、[结果解释](https://developer.apple.com/help/app-store-connect-analytics/acquisition/product-page-optimization)。不要为做营销测试打断当前审核。

## 下一次执行的最小动作

先用已准备的清单场景稿，在一个Owner已有、允许此内容的渠道做第一轮10人自愿体验。Agent负责素材、链接、结果台账和问题归纳；Owner只需在实际外发前指定已有渠道／账号及允许发布的稿件。没有这项具体外发指示前，继续完成内容和提供方缺口，不能冒充已发帖或自己制造用户反馈。
