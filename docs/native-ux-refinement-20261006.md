## 问题、原因与修正

1. 指南目录闪现“正在加载你的复核状态”：实际用户截图中静态目录已经显示，异步旧自报状态却插入无关加载行。现在目录静默读取旧状态，保留真正失败的说明和重试；不是掩盖错误。
2. 指南重复来源与确认框：官方操作链接继续按准备／身后／文件阶段展示，删掉原生重复原始 URL 折叠区和“我已阅读”操作。历史记录、底层服务、原始来源和复核日期保留；没有影响注册／共享／导出的法律或安全确认。
3. 官方链接：检查 18 平台当前官方路线，修正 Microsoft、X、Coinbase 和 Bitwarden 入口，区分 1Password 生前恢复准备与身后限制。官方站点可改变地址、要求登录或限制地区，无法承诺永久可用；不为没有专门表单的平台编造继承入口。[逐平台来源和限制](qa/ios-ux-refinement-20261006/official-links.md)。
4. 安全与隐私：删除两个静态教学卡片，将许可／致谢移为该页较轻的次要入口，完整许可资源保留。新增真实密码重置入口，说明通行密钥／二步验证管理目前未接入，不能据此判断保护关闭。
5. 套餐卡片跳动：共享 DisclosureStyle 同时对 Form 高度、移入／模糊转场和按压缩放施加运动。现在使用无动画事务、identity 转场和普通按钮样式，保留折叠语义、旋转箭头和点击面积。此为代码层修正，尚无本轮原生帧级／交互验证。
6. 语言与外观：登录前后 Profile 均进入二级“语言与外观”，移除 Profile 右上角两个大控件。外观继续使用既有本机偏好；语言继续由 iOS 原生逐应用设置持久化，保留系统重启及先保存草稿的提示，不重建整个页面树。
7. 登录会话：只显示当前设备退出；后台撤销全部会话、失效恢复和安全状态清理仍保留。
8. 事项与首页：列表筛选真正使用七种 MatterCategory，与状态／负责人进度／接收人复核分离。首页仅在已有必填查找信息缺失时建议补充具体项目，否则“查看你的事项”；保存的 `needs_review` 原值不变，主人侧中文改“待整理”。共享复核仍是独立、可选的已授权功能，不因分类自动发起。
9. 当前账号：Profile 显示服务端当前会话选定的账号名和可用的已验证邮箱；不猜测邮箱、不以原始 Auth0 subject 代替账号名，不把另一个会话的缓存继续显示。无邮箱时显示准确原因和短账号参考，暂时失败可重试。

## 身份与安全边界

身份读取合同在 [共享接口说明](account-identity-display-20261006.md)。原生请求 `GET /v1/account/identity`，仅 404 时兼容旧版当前账号 profile；401／403／500／格式错误不绕过。内存状态同时检查当前 UUID、请求代次、取消状态及返回账号绑定，退出／切换账号会清理旧结果。姓名和邮箱按用户文本原样显示并标记 privacySensitive，不写日志、偏好或数据库。

密码重置只使用既有 Auth0.swift 3.0.2 公共 Authentication API 与既有 `Username-Password-Authentication` 连接。用户必须自行输入邮箱并明确点击；打开页面、刷新身份和编辑文字均不发送。界面不采集新密码，结果使用条件式反馈避免枚举账号，不宣称邮件已送达。网络、频率限制和其他失败映射为安全双语文字；导航取消会丢弃晚到结果，但已发出的请求不能“撤回”。没有新增管理密钥、授权范围或持久访问。

当前令牌和连接未提供可验证的 MyAccount／安全管理门户能力，故没有通行密钥／MFA 的装饰性按钮。若后续接入，先确认 Auth0 实际支持的生产能力、细粒度授权与重新认证合同，并取得所需安全配置批准。不能根据现有证据推断当前用户已／未启用 MFA。
