# Rillora Web 新用户验收报告

**测试时间：2026-10-04 18:43–19:26 UTC**  
**结论：主链路可用；本轮实测完成，但不宜宣称整站验收通过。**

从匿名官网开始，经新账号注册，实际创建全虚构事项和联系人，走过创建、取消保护、刷新草稿恢复、保存、编辑、搜索、分享字段预览、明文副本下载、归档恢复，以及窄屏 Web 和键盘回归。

最值得先改的不是视觉风格，而是三类问题：**下一步做什么不清楚、不可点击的原因不清楚、状态与焦点在不同页面之间不连续。**

## 2. 优先结论

### 先修的已复现问题

1. **INT-01 / P2：关闭事项抽屉后焦点回到页面根，键盘使用者丢失位置**
2. **UI-01 / P2：窄屏把 Draft 等事项状态文字隐藏，只剩颜色圆点**
3. **UI-02 / P2：Activity 的日期时间被挤成竖向碎行，桌面和窄屏均出现**

### 最影响新用户完成任务的体验建议

1. **UX-01 / P1：把“1 of 5 essentials / Continue next step”改成可理解、可到达的任务清单**
2. **UX-02 / P2：邀请邮箱无效时给出明确错误，并使禁用按钮看得出来**
3. **UX-03 / P2：明确 Directions 与 Notes 的关系，避免以为文字说明已经分享**
4. **UX-04 / P2：把 Start Here guide 的导出用途写清楚，和入门教程区分**

这里的 P1 表示优先影响新用户完成，不表示安全漏洞、数据丢失或服务中断。未发现足够证据支持 P0 结论。

## 4. 已复现问题：步骤、影响与修复标准

### INT-01 / P2：关闭编辑抽屉后丢失键盘位置

- 复现：事项列表对文档行按Enter → Edit matter → Escape → Tab
- 预期：焦点恢复至原事项行，继续同级导航
- 实际：焦点变为页面根；下一次Tab跳到顶部Appearance。第二次仍一致
- 影响：键盘使用者在每次查看后重新遍历；长列表更明显
- 建议：保留触发元素引用，关闭/返回时恢复focus；触发器不存在时落到合理替代位置
- 验收标准：鼠标关闭、Escape、浏览器返回都回到原事项；滚动位置不跳；不把焦点留在被移除节点
- 证据：52–53

### UI-01 / P2：窄屏把状态简化成无文字圆点

- 复现：桌面查看Draft事项 → 缩窄至500/400 CSS
- 预期：用户仍能读到状态含义
- 实际：Draft文字不见，只剩浅色圆点。AX仍有文字，但不能替代视觉呈现
- 影响：无法直接区分Draft/待审阅/已添加说明，颜色辨识困难者尤其受影响
- 建议：保留紧凑文字badge，必要时另起一行
- 验收标准：各状态在320/375/400/500宽度可读，不只靠颜色，不挤掉标题和操作
- 证据：44对比45–46、50

### UI-02 / P2：Activity日期时间碎成竖列

- 复现：添加长标题文档、归档/更新事项 → Activity；400 CSS和1181 CSS均观察
- 预期：动作、事项、时间都可扫读
- 实际：时间呈Oct / 4, / 2026, / 12:05 / PM；带目标的事件明显，无目标事件可正常一行
- 影响：行高膨胀、时间难读，很难追溯操作
- 建议：动作与标题一行/两行，时间独立一行；避免目标链接与时间共享极窄网格列
- 验收标准：普通/长中英标题、带/不带目标事件在桌面与窄屏都不逐词挤压
- 证据：59、61

## 5. 体验改进：用户为什么会卡住

### UX-01 / P1：下一步不说明缺什么

建立事项、补Request closure和Notes、状态改Directions added后，My plan为1 of 5 essentials。Continue next step仍打开相同事项编辑页，焦点在Category，既不解释五项也不定位缺项。**这是完成路径不明确，不是已证明的进度计算错误。**

改法：五项可展开清单、明确完成条件、带动词的下一步按钮（如添加可信联系人）；每一步指向对应操作而非通用编辑。证据39–40。

### UX-02 / P2：邀请邮箱错误时没有解释

输入not-an-email，随后点击事项使邮箱失焦，仍无格式错误；CTA在AX中disabled，但保持高亮橙色。与注册页明确错误反馈形成反差。

改法：失焦/提交给可关联字段的错误文字；禁用原因就地可见；视觉状态一致。复测需覆盖空值、空格、缺@、误贴空格、合法邮箱和键盘提交。证据32、62。

### UX-03 / P2：Directions不包括用户写下的Notes

Directions预览仅包含Provider / Location / Wishes。Notes里的具体步骤要选Details才出现；同时也会共享masked hint与importance。实际预览字段符合选择，**未发现越权泄露**，但档位名称容易让人以为“说明都发过去了”。

改法：清楚列出包含/不包含字段，显著注明Notes；最好允许按字段决定。最终确认前默认展开接收人预览。多行Notes在预览中被压成连续段落，也建议保留换行。证据30、63。

### UX-04 / P2：Start Here guide被用作导出工具，却像入门教程

从My plan点Review Start Here guide，第一问是Who is this copy for?，之后Review / Format / Save。用户要找“下一步怎么做”，却进入副本制作。

改法：改名为Preview/export directions guide；与Quick start guide和计划清单分别命名。证据34–38。

### UX-05 / P2：关键字段/类别术语不统一

入门Category是Account / Asset / Crypto，正式表单是Online account / Financial asset / Crypto asset；Preferred outcome在共享预览叫Wishes，在导出里又变Direction。导航Account inheritance的页面标题是Official guides。

改法：建立面向用户的小词表，同一个实体/动作保持一致；需要改变粒度时加一句解释。证据18–19、30、60。

### UX-06 / P2：注册连续性弱

官网和App浅色，注册承接突然深色，logo简化；Email首步没有回Rillora入口。输入邮箱后才出现passkey介绍，备用按钮只写Continue without passkeys，随后才是密码。

改法：保持品牌/外观；清楚返回/取消；预告注册步骤；把备用方式明确为“使用密码”。条款前置条件可放在入口之前或解释禁用原因。证据03、09、13。

### 次要建议 / P3

- 取消Access步骤会保留Person步骤已保存的联系人；Not invited状态正确，但Discard changes应说明只丢弃分享设置，避免用户以为取消整个创建，33
- Shared reviews设置弹窗内未解释计划限制；没有scheduled review时仍显示Pause reviews，55–56
- Planned Web pricing边界清楚，但Shared reviews缺少定义；App价格只写$88.99，官网US$88.99，可统一币种，06、54
- 官网首屏“重要事项的私密地图”较抽象，建议直接给一条“记录位置→指定人→下一步”的具体样例；不是需要推翻现有视觉风格，01–02

## 6. 待产品确认项

**OBS-01：恢复事件未出现在Activity UI。** 归档后成功Restore privately，再新建文档；Activity和刷新后显示归档与之后新建文档，没有观察到恢复事件。需确认事件覆盖范围和延迟，不能直接定性为后端日志丢失。若此处定位Private audit，建议提供恢复事件并标明恢复为private Draft。证据44、59、61。
