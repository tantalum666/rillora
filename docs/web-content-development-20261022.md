## 实施顺序

1. 合入已上线Node22.23.4源补丁；保留此前三种实际应用基线的部署记录，避免回退安全运行时。
2. 新增独立内容模型与数据库迁移。文件、原声及办理材料默认本人私有；未来指定关系不能自动变成当前读取权限。
3. 建立有界文件保存、原声录制／播放、可核对文字和本人导出／删除。应用层信封加密沿用现有受管KMS设计，不宣称E2EE。
4. 办理包包含本人确认的目标、材料、官方指引、负责人、办理状态和回执信息。已提交／已完成是明确来源的用户记录，不冒充机构批准。
5. 新的当前共享必须是本人明确选择的独立授权和内容版本，复用已接受的身份关系；收件人不另行付费。撤销、联系人归档、不可披露事项、过期权益与旧副本均按现有边界处理。
6. Web采用独立能力入口、懒加载和双语文案；文件与录音处理真实失败／取消／重试、权限拒绝和换账号状态。
7. 仅合成数据验证新增API、数据库隔离、文件篡改、边界、共享／撤销、到期可取回、删除／恢复及旧iOS接口兼容；真实用户数据不做破坏性测试。
8. 候选环境先行，保存备份和实际模板变化；通过后发布Web及兼容API，核对线上文件／功能开关和旧审核路径。不会以build成功替代实际部署证据。

## 不变的安全与商业边界

- 地图不存银行卡密码、完整助记词或可直接转账的秘密；文件／录音不提供绕过该限制的入口。
- 生产没有已验证的真实身后放行通道。事实核验、身份、法定权限及Rillora范围四门继续适用；本次准备功能不顺带开通自动死亡判定、未经证实的人工解封或HealthKit释放。
- 尚未开放的身后交付明确显示为准备中，不能收集真实死亡证明制造已提供服务的印象。当前明确共享仍可独立使用。
- 容量、录音时长、处理频率采用明确有界的首版配置并记录成本假设；不承诺无限、永久或12个月已批准服务期。
- 本人已有内容仍可读取、导出和删除，停止订阅不会解除封存或自动删除核心记录；新增文件保留／取回规则必须在开放前写清。
- 外部转写如启用，必须使用已选区域内的明确处理方、最小临时存储、限额、失败回收和本人文字确认；不将原声偷偷发给未配置模型服务。
